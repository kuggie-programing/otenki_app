防災アプリ auth5 修正・機能復元版
2026-09-11 / 更新番号 2026.09.11-auth5

最初に：これはコードと公開用ファイルの更新セットです。
既存のサーバーをこちらから更新したり、登録データを復元したりはしていません。
確認済みの範囲と未確認の範囲は TEST_REPORT.txt に記載しています。

■ 今回の更新方法（Windows / VS Code）
1. アプリを起動しているターミナルで Ctrl+C を押し、いったん止めます。
2. 現在のアプリフォルダーを、念のため丸ごと別の場所へコピーします。
   特に実際の otenki_data.json、.env、鍵ファイルは必ず保管してください。
   Gitのコミットだけでは、Git管理外の登録データのバックアップにはなりません。
3. このフォルダーの中身を、今の main.py がある場所へコピーします。
   同じ名前のコード・画像は置き換え、新しい app_core.py / api-config.js /
   quiz.json なども一緒に置いてください。HTMLだけの交換では動きません。
   既存の api-config.js を自分で設定していた場合は、元の値を控えてください。
   このZIPには空の otenki_data.json、実際の.env、秘密鍵を入れていません。
   現在の登録データや鍵を消す必要はありません。
4. VS Codeのターミナルで、main.py のあるフォルダーから実行します。

   python -m pip install -r requirements.txt
   python -m unittest test_core test_app -v
   python main.py

   テストは一時フォルダーに試験用データを作り、実際の登録データには触れません。
   「OK」が出たら起動してください。Python 3.11以降を推奨します。
   Pylanceの警告が残る場合は、VS Codeで選択中のPythonと、
   上のpipを実行したPythonが同じか確認してください。

5. ブラウザで http://127.0.0.1:5000 を開きます。
   index.html のダブルクリックでは開かないでください。
   最初の更新時はオンラインで開き、画面を再読み込みします。
   Windowsでは Ctrl+F5、インストール済みPWAは一度閉じて開き直してください。
   ログイン画面の下に「更新版 2026.09.11-auth5」が出るのが目印です。
   ブラウザの「サイトデータを全部削除」はしないでください。
   知恵貯金・安心メモは端末内に保存されており、削除すると失われます。

■ 接続先がいちばん重要
旧版には特定の外部サーバーへ接続する固定設定がありました。
今回は「この画面を配信しているPythonサーバー」に接続するのが標準です。
ローカルのPythonと公開サーバーでは、登録データは別です。
同じキーでも、別サーバーにアカウントがなければログインできません。

・ローカルで使う：元の登録データを、実際に起動する main.py の場所へ残します。
・今の公開サイトを更新する：フロントだけでなくPython側もこの版へ更新し、
  元の OTENKI_DATA_FILE と永続ディスクを維持します。
・画面とAPIを別サービスに置く：api-config.js の OTENKI_API_BASE_URL に
  「実際にアカウントを登録したAPIサーバー」のHTTPS URLを指定し、
  サーバーの OTENKI_ALLOWED_ORIGINS に画面側のオリジンを設定します。
  第三者のサーバーや、実在しない仮のURLを入力しないでください。
  新しい encoded ヘッダーに対応するため、API側 main.py も同時に更新が必要です。

ログイン画面の「接続先・ログインできないとき」→「接続を確認する」で、
接続先とアプリの更新番号を確認できます。名前や秘密キーは表示しません。

■ キーの使い方
・ログインには登録済みキーだけでよく、表示名は新規登録の時だけ必須です。
・「表示」で入力を確認できます。Enterキーでもログインできます。
・日本語、全角、絵文字を含む既存キーに対応し、APIヘッダーにはUTF-8/Base64で送ります。
・大文字と小文字、半角と全角は別のキーです。勝手に同一化はしません。
・前後の空白だけを取り除きます。キーそのものを自動変更・再発行はしません。
・「新規登録用のキーを作る」は新しい人のための機能です。
  既存アカウントのキーを忘れた時に押しても、元のアカウントには戻れません。
・間違ったキーや未登録キーはログインを拒否します。
・10回程度失敗が続くと、その接続元の試行を約1分制限します。
・標準では現在のタブにログイン状態を保存します。
  「この端末にログイン状態を保存する」を選んだ時だけブラウザを閉じても保持します。
  共有端末ではチェックしないでください。
・ログアウトでキーとログイン状態を消しますが、知恵や安心メモは消しません。

■ 「登録データがありません」と出た場合
過去のZIPには空の otenki_data.json が含まれていました。
以前それで実データを上書きした場合、キーの入力処理だけ直しても戻せません。
元のサーバー、元フォルダー、バックアップ、OneDrive等のファイル履歴を確認します。
この版は .bak を作成しますが、既に消えた過去データを生成するものではありません。
別の新規アカウントを作っても、消えたアカウントや友達接続は復元されません。
破損したJSONを見つけた時は、空データで上書きせず503で止めるようにしています。

■ 公開先での注意
・HTTPSを有効にして、実際に登録したデータを永続保存してください。
・JSON保存方式のため、Pythonのアプリプロセスは1つで動かします。
  Gunicornは --workers 1 を維持し、複数コンテナー/複数サーバーで同じJSONを共有しないでください。
・公開先では Procfile の起動コマンドを使います。
  Windowsのローカル起動は python main.py でWaitressを利用します。
・OPENWEATHER_API_KEY とVAPID関係の既存設定を、公開先の秘密の環境変数へ設定します。
  VAPID_PUBLIC_KEY はブラウザのapplicationServerKey用の形式を使います。
  空欄のままでは天気取得・実Push配信は使えませんが、ログイン処理は待ち続けません。
・通知用の秘密鍵が過去に公開GitHubや公開フォルダーへ出ていた場合は、
  露出状況を確認して更新してください。その際は端末の通知登録もやり直しが必要です。
・この版では公開できるファイルだけを許可し、main.py、登録JSON、.env、鍵ファイルは配信しません。
・Web Push配信は登録した端末への通知で、緊急通報機関への連絡ではありません。
・一般公開前に、実際の配信先・スマートフォンでログイン、再ログイン、
  通知、オフライン再起動を確認してください。セキュリティ監査を完了した製品という意味ではありません。
